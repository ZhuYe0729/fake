优先完成原四组核心配置：B8/S2048/O64、B4/S2048/O64、B8/S4096/O64、B8/S2048/O128，包含三种Prefill-only和四种P+D。使用BF16、HAWQ/DASO各两个冻结点，PP共同端点只测一次；每卡独立三轮，每case五预热/十计时，BF16首尾归一化。完整三轮最早完成的卡作为主结果，其他卡结果分列，不按速度胜负选卡或跨卡拼轮次。

核心完成且余量充足时，再测B8/S2048/O256和O512的长Decode速度；还有余量则补这两组的64窗真实KV ΔNLL。任务精度沿用050原完整任务和生成上限256；测速强制输出512不代表修改了原任务精度协议。

同一轮中的正式模型工作串行，固定CPU组/NUMA。入场后先以小CUDA上下文探针校准全卡应用显存与自己PID显存的统计差额；正式过程中同时看全卡显存、可见PID和未归属差额。可见外部PID，或自身分配已稳定时连续两次超出校准差额256MiB，则终止自己的进程；进程退出后卡也必须恢复低占用。资源归属异常的整轮尝试保留，待重新连续空闲后重做。**未归属增长并不单独证明存在外部任务**，也可能涉及统计或驱动归属差异；本轮按预先设置的门槛保守排除整个尝试，不将其作为干扰原因的确证。5%速度波动只标记，不触发删除或挑轮。

**显存口径已核实：** 本机NVML v1的used包含约497MiB驱动保留；使用NVML v2的`total-free-reserved`得到应用实际分配量，分别记录reserved及原字段，防止把驱动保留误当他人占用。参见[NVIDIA保留显存说明](https://docs.nvidia.com/deploy/nvml-api/api/structnvmlMemory__v2__t.html)。采样仍不能排除极短或低于观察阈值的干扰。

权重硬链接复用051/050，数值内核、引擎容量和核心输入与049一致。原精度、旧速度和051受中断首轮都保留。所有空闲采样、入场证据、上下文校准、命令/代码版本、逐次计时、未成功轮次及新长Decode结果存本目录。

**初始化监控修订：** 首个完整轮次之后发现，自身CUDA进程尚未进入NVML归属列表时，连续的0字节不应被当作“自身分配已稳定”。后续只在自身归属显存非零且稳定时确认未归属增长，可见外部PID仍立即中断。旧完整首轮按原更严格规则接受；逐任务保留监控代码版本，核验器分别复算两版谓词，并强制其余数值代码完全相同。修订前文件和被中断尝试保留，九小时截止不变。

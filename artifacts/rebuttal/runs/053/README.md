# 053 — 空闲窗口内的Qwen完整对照块

[结果与表格](../../responses/reviewer2/qwen_night_cohorts_run053/README.md) · [实时调度](results/worker.json) · [空闲采样](results/idle_status.json) · [设计](configs/design.json)

九小时观察窗口仍截至 **2026-10-29 01:12:53 UTC**。每30秒观察八卡，应用显存<128MiB、利用率≤5%、无可见计算/图形PID并连续90秒才开测（四次连续采样）。053首个正式块之前，根据实际窗口将准入时长由五分钟经三分钟调整为90秒；[窗口统计](../../results181/reference/idle_duration_90_revision/window_summary.json)和修订前配置保留，其他资源门槛不变。驱动保留显存单列；自身归属已就绪且分配稳定后，连续两次超出校准差额256MiB，或出现可见外部PID，均中断自己的工作。未归属增长不能单独确证外部任务。每个模型退出后仍需三次低占用检查；不处理他人的进程。

052获得过GPU3完整一轮，但多次在后半段资源异常，因缺BF16收尾而损失整个较长对照。053独立重新测量，不混用052；仅将完整对照拆为以下四类：

| 优先级 | 对照组 | 配置 | 每轮唯一模型进程 |
| --- | --- | --- | ---: |
| 1 | core_pp | B8/S2048、B4/S2048、B8/S4096，O=1 | BF16首尾＋三个Prefill策略，共5个 |
| 2 | core_pd_*（四个独立块） | B8/S2048/O64、B4/S2048/O64、B8/S4096/O64、B8/S2048/O128各自一块 | 每块BF16首尾＋HAWQ/DASO各两点，共6个 |
| 3 | decode256 | B8/S2048/O256 | 同上，共6个 |
| 4 | decode512 | B8/S2048/O512 | 同上，共6个 |

每组按原冻结全策略顺序筛选后执行三轮：Prefill有三个不同顺序；P+D第1/3轮顺序相同，第2轮反向。每case五预热、十正式计时，使用**自己同块、同负载的BF16首尾**归一化。同一张卡五个核心组各三轮才算核心完成，两个长Decode组各三轮才算长Decode完成；以最先满足条件的卡为主结果，不按速度胜负选卡，不跨卡拼轮次。核心117个case轮次、长Decode36个，与052目标计时数相同。逐配置块需要更多模型初始化，以缩短完整对照必须保持安静的时段；初始化仍不计入单次推理计时。

持续受监测的同一租用期内可串行完成多个完整块。资源事件只使当前未完成块失效；此前已完整通过的块保留。再入场重新等90秒。全部尝试、命令、监控与代码快照留存，5%速度波动只标记，不据此删轮。

策略、权重、内核、引擎容量和计时边界沿用052/049；experiment.py只新增组选择，不改变算子或计时。权重硬链接复用，原任务精度050和核心逐配置NLL049保持不变。长Decode测速完成且时间充足后，补两组64窗真实KV NLL；原下游任务生成上限256不改。

CPU回放测试仅使用临时目录中的旧数据，**不是新测量**；通过部分场景、完整合并和错误总表拒绝检查，见[核验记录](../../results181/reference/cohort_replay_validation.json)。正式表格仅读取本目录真实accepted记录。

## 22:46 UTC 起：先补缺失配置

多卡反复在空闲后重新被占用，新卡从已经完整的Prefill重测会拖慢覆盖。外部[coverage053入口](../../results181/coverage053.py)接替原派发，调用同一冻结校准、租用、计时和退出检查函数，按冻结组顺序跳过已在任一卡完整三轮的组，优先补缺。入口请求与SHA保存在results/coverage_dispatches；同一driver锁确保没有并发控制器。

**原同卡全场景主结果规则保留。** 另交付[按配置分卡覆盖CSV](../../responses/reviewer2/qwen_night_cohorts_run053/table2_coverage.csv)：每个场景仍须同一卡三轮，选最早完成的设备；不同配置或两个场景可用不同卡，表中注明Prefill/P+D卡号，不跨卡拼同一场景的三轮，不按速度好坏选卡。未齐场景保持待测；覆盖齐全也不冒充同卡全场景主表。已完成的不利中心P+D三轮仍保留为其覆盖结果。

核心覆盖后有35分钟余量可继续长Decode，长速度覆盖后有25分钟余量再补NLL；原01:12:53 UTC截止不变。所有旧完整块、被中断块与暂估记录保留。[派发逻辑夹具](../../results181/reference/coverage_dispatch_validation.json)及[错误覆盖GPU拒绝](../../results181/reference/coverage_export_validation.json)均只是CPU检查，不是新实验。

若核心与长速度已覆盖完整、原控制器已退出，但不足25分钟，仍有至少15分钟可用[finish_quality053](../../results181/finish_quality053.py)调用冻结质量函数补跑。入口先检查同一卡三轮覆盖、代码/权重身份及driver锁，再记录请求SHA；实际模型检查与五策略×两长度×64窗验收不变，仍按原截止停止。

### 1．质量预算的实测满足率及违约情况

**问题：选出的策略在实测 NLL 上多大比例满足质量预算？是否出现违约，特别是在预算较小时？**

我们区分“在预测模型下满足预算”和“在完整模型实测中满足预算”。预算针对完整策略在评测数据上的平均 ΔNLL，而不是要求每个文本样本都满足相同上限。

为直接检查这一点，我们在 Qwen3-8B 的 Prefill+Decode 场景中，统计了预先指定的 9 种负载、两档质量预算 ε=0.01 和 0.07，共 18 个“预算—负载”设定。每个设定使用原 DP 求解器及七候选扩展选取策略，再在 100 个固定 WikiText 测试窗口上测量相对 BF16 的平均 ΔNLL；跨负载保持质量模型冻结，未使用这些测试结果筛选策略。

**18 个设定中，17 个满足实测平均质量预算，满足率为 94.4%；1 个超限，观察到的违约比例为 5.6%。** ε=0.01 时为 8/9 满足，ε=0.07 时为 9/9 满足。唯一超限发生在 B=8、输入512、输出64、ε=0.01：实测平均 ΔNLL 为 0.011959，超过预算 0.001959 nats/token。这些设定复用 16 套不同策略和共同文本，因此该比例是这组完整预设网格上的观察值，不应解释为 18 次独立试验估计出的普遍违约概率。

这一结果表明，质量代理能够在大部分已测设定下得到满足预算的策略，但不能提供严格的实测保证。原论文在 Llama-3.1 留出策略上报告的 ΔNLL MAE 为 0.0413、Spearman 相关系数为 0.963，也支持其整体预测和排序能力；该指标来自另一模型和策略集合，不能直接作为上述 18 个设定的预测误差。

对于很紧的预算，相同绝对量级的代理残差和有限样本不确定性，相对于预算会更加显著。本次唯一超限也出现在较紧的 ε=0.01 下。不过，该实验尚未将代理误差与样本波动的贡献分离，也不能仅凭 NLL 超限较小就推断下游任务完全等效。我们会明确将其表述为经验性预测约束；对于需要更严格实测满足的部署，可以在独立验证集上增加完整策略校验与余量，再在未参与选择的测试集上报告结果。

来源：[18 个完整设定、逐窗数据与核验](responses/reviewer1/pd_quality_budget_expanded/README.md)。

### 2．阶段异构表示的峰值显存、主机缓存与部署收益

**问题：不同阶段采用不同权重表示，会引入多少额外峰值显存或权重存储？是否削弱部署加速？**

阶段异构压缩确实引入额外的表示存储和预取管理。当前优化器主要针对质量预算下的延迟最小化，尚未将峰值显存作为显式优化约束；运行时已采用相同表示共享、按层复用 GPU 缓冲区，并在 CPU 端缓存可切换的阶段权重。

**表 R1-1．Qwen3-8B 原主表执行路径的内存占用**

| 方法 | 峰值显存 GiB（Torch分配） | 主机阶段权重缓存 GiB |
| --- | ---: | ---: |
| BF16 | 23.04 | 0.00 |
| SmoothQuant INT8 | 17.64 | 0.00 |
| DASO（均衡） | 15.55 | 8.24 |
| DASO（速度优先） | 16.27 | 8.76 |

该表与 Qwen 主表采用同一 arena/Graph 执行路径，B=8、输入2048、输出64，固定 6 GiB BF16 KV cache，取三轮中位数。GPU 列为 Torch 分配峰值；Host 列仅为额外的持久阶段权重缓存，不是 CPU 总内存或 checkpoint 磁盘大小。BF16 的 Host 为0，表示没有这项额外缓存。Host 与 GPU 是不同资源，不能相加成显存占用。

在这些代表配置下，DASO 的峰值显存仍比 BF16 低约 32.5% 和 29.4%，但另外需要 8.24/8.76 GiB 的主机阶段缓存。该缓存不直接占用 GPU 显存，可以复用已构建的表示，避免反复加载或构建；它是模型驻留期间的持续 CPU 内存需求，仍需要足够的主机容量和传输带宽。

在执行开销方面，vLLM 集成使用独立 copy stream 与事件依赖，在某层完成 Prefill 后准备其 Decode 表示，使复制与后续层 Prefill 计算重叠。原论文 Llama-3.1 代表点的诊断记录为累计复制工作 354.94 ms、暴露复制等待 1.92 ms；另一次同配置运行时消融中，异步预取使 E2E 中位数从 1625.87 ms 降至 1521.73 ms，约降低 6.4%（7 次配对中5次更快）。这些结果说明了 overlap 对关键路径的作用，不表示所有部署中传输成本为零。

主表 E2E 已包含本批 Prefill→Decode 的实际执行和切换；下一批开始前的恢复另外计入 cycle。上述 Qwen 两个 DASO 点的恢复时间为约 90/102 ms，计入后 cycle 仍达到 BF16 的 1.844×/1.842×。因此，包含这部分成本后仍有实际加速。

我们也承认，即使峰值短暂，它仍会影响设备容量、KV 空间和可支持的并发。现有 overlap 主要以降低关键路径延迟为目标，后续将考虑显式显存约束、更细粒度的受限预取及缓冲区生命周期管理，进一步改善内存与延迟的折中。

来源：[同轮内存、延迟及 overlap 证据](responses/reviewer1/phase_memory_reply/README.md)。

### 1．vLLM continuous batching 与 chunked prefill（W1）

我们同意，在 continuous batching 和 chunked prefill 下，同一次 forward 可以包含不同请求的 Prefill 与 Decode token；vLLM 官方也明确描述了这种调度方式。[vLLM chunked prefill 文档](https://docs.vllm.ai/en/v0.11.1/configuration/optimization/#chunked-prefill)

这种混合不要求所有 token 行采用相同的 Linear 权重。Linear 按 token 行计算，因此可以根据调度器提供的原始 prompt 长度和当前 token 位置，将输入行分成 Prefill 与 Decode 两组，分别调用对应的阶段权重与 kernel，再将结果恢复到原始行顺序。Attention 保持原来的请求边界、位置和 KV 元数据。这样无需改变 Transformer 结构，但需要扩展运行时的 Linear 路由；长度为1的 prompt chunk 仍归为 Prefill，不能只按 query 长度判断阶段。

我们已有真实 vLLM V1 的混合调度扩展，在 chunk token budget=1024 下执行上述路由，并核验每次 forward 的阶段 token 数。

**表 R2-1．真实 chunked-prefill 调度下的阶段路由**

| mixed负载 | 每burst真实mixed forward | DASO均衡 E2E×BF16 | DASO速度点 E2E×BF16 |
| --- | ---: | ---: | ---: |
| B8 / S2048 / O64 | 15 | 1.348 | 1.225 |
| B8 / S512、2048交替 / O256 | 10 | 1.013 | 1.210 |

表中 speedup 为相对同场景 BF16 的 E2E 加速比，包含实际路由执行成本。实验覆盖九种方法、两个负载、三轮；逐层同分组 kernel 参考检查及 BF16 no-op 一致性检查通过，并对实际 mixed 执行另测了每方法/负载64窗 NLL。

这项扩展采用两阶段表示同时常驻的 eager 路径，与原主表的单 arena/Graph 路径分开报告；它会引入额外驻留与 gather/scatter 成本。现有请求在起始时一次提交，尚未作为持续错峰到达的生产负载测试。上述结果直接支持“同一 forward 中可以执行不同阶段权重”，其生产性能范围仍需按具体调度进一步验证。

此外，PD 分离提供了自然的另一种部署方式：Prefill worker 使用 Prefill 配置，Decode worker 使用 Decode 配置，并通过兼容的 KV cache 交接。vLLM 已提供不同实例通过 KV connector 交接的机制。[vLLM PD 分离文档](https://docs.vllm.ai/en/v0.11.1/features/disagg_prefill/)

这说明阶段策略与该架构相容；我们尚未完成双 worker 的实际 KV 交接测试，因此不将其作为已测分布式加速结果。实际集成还需核验 KV 格式、位置、首个生成 token 的处理及传输成本。

来源：[混合调度结果、实现与范围](responses/reviewer2/mixed_pd_compatibility/README.md)。

### 1．与硬件感知 NAS 的关系与贡献定位

我们认同，离散候选、质量/延迟代理以及资源约束搜索，在 NAS 和混合精度优化中已有充分先例。我们会补充 [ProxylessNAS](https://arxiv.org/abs/1812.00332)、[FBNet](https://arxiv.org/abs/1812.03443) 与 [BRP-NAS](https://proceedings.neurips.cc/paper_files/paper/2020/hash/768e78024aa8fdb9b8fe87be86f64745-Abstract.html) 等讨论；其中既有直接面向目标硬件优化的工作，也有通过性能预测减少搜索测量成本的工作。

本文贡献应聚焦于固定预训练 LLM 的部署策略：在真实推理后端中联合选择每个 Linear、每个阶段可执行的量化与稀疏表示，校准局部扰动到完整策略质量的关系，并管理不同阶段权重表示的生命周期。我们不会将使用预测器、硬件延迟或背包求解这一通用形式本身作为独有创新。

新增的异构分配与同候选代理对照见 [R2 第2点](#r2-experiments) 和 R3 表 R3-1；实际执行、内存和准备成本分别独立报告，以便区分搜索形式与具体部署系统的贡献。

### 2．不同精度/格式之间的转换与切换开销

我们区分“权重的内部压缩格式”和“相邻模块之间的 activation 接口”。已实现后端在 Linear 内完成其激活量化、缩放或打包，并返回 BF16 输出，因此不同模块的内部权重格式无需直接成为下一模块接收的激活格式。

**表 R5-1．实际 Linear 边界检查**

| 配置 | 实测边界条数 | 输入 | 输出 |
| --- | ---: | --- | --- |
| INT8/FP4阶段混合配置 | 256 | BF16 | BF16 |
| SmoothQuant INT8 | 256 | BF16 | BF16 |
| FP8 | 256 | BF16 | BF16 |

上述768条记录来自三种配置、每种128个 Linear、两个阶段的真实 forward。另有连续 MLP 方法对检查。内部量化和 metadata 工作计入完整 kernel 画像；BF16 接口一致不表示内部转换成本为零，也不能保证任意融合、布局或 cache 效应可完全按层相加。

阶段权重搬运与下一批恢复是另一类开销，由运行时 overlap、实测 E2E 和完整 cycle 评估，详见 [R1 第2点](#r1-memory)。原加和代理并未显式建模所有策略相关交互；我们将说明这一近似，并以 [R3 第2点](#r3-latency) 的整策略预测误差与实际延迟补充验证。

### 3．压缩候选集合的扩展

我们补充真实 INT8 W8A8、SmoothQuant INT8 和 FP8 相关候选与对照，以扩展原五类后端，完整模型结果见 [Reviewer 2 第2点](#r2-experiments)。

候选空间仍受当前硬件和已实现 kernel 限制，尚未覆盖 INT2、任意稀疏率等所有可能选项。框架的动作是可执行的压缩后端，不以未实际实现的低 bit 标称值代替可部署候选；新增后端也需要重新测量成本和扰动。

### 4．“相同模块输入”的采集方式

我们从未压缩的 BF16 参考模型获得模块输入。在逐层前向中捕获同一份输入 tensor，分别调用 BF16 参考 Linear 与各候选完整后端，累积输出平方误差及参考输出能量。候选输出不会替换参考主干继续传播的激活，因此每个候选面对的是相同的参考输入。中间激活按层暂存，不要求永久保存全模型的所有激活。

需要进一步说明，局部 continuation 特征来自 teacher-forced 序列的 continuation 位置，并以批量方式送入候选 Linear；这不是压缩 KV 路径中的逐步 Decode 重放。该近似用于校准质量代理，完整策略的质量标签及最终测试另通过真实 vLLM KV 执行获得。我们会将局部扰动测量与完整模型质量评测明确区分。

来源：[输入捕获与误差聚合的实现说明](responses/reviewer5/overnight_run008/IDENTICAL_INPUTS.md)。

### 5．反约束：给定延迟上限时优化质量

可以将问题改写为：在预测延迟不超过上限的条件下，最小化预测质量损失。对于相同的模块动作和加和代理，动态规划仍具有最优子结构；若交换 DP 的成本与目标，需要控制延迟离散化误差，或直接求解对应整数规划。它是约束方向的交换，不能将预测可行直接解释为实测 SLA 保证。

**表 R5-2．正反约束与实测延迟检查**

| 检查内容 | 检查范围 | 实际结果 |
| --- | --- | --- |

| 原绝对延迟上限 | 18套配置，每套24次计时 | 0次观察超时 |
| 首轮校验后检查后两轮 | 36个目标设定，复用17套配置 | 36个均可行，后两轮0次观察超时 |

8个一致性检查针对固定代理，支持反约束求解正确性。实测部分分别报告原绝对延迟上限检查，以及另一个规则预先固定的分割校验：后者用 round0 最大计时样本×1.05作为筛选依据，再检查 round1/2；36个目标设定复用17套策略，E2E 与 cycle 分别定义上限。

分割分析在三轮数据收集完成后执行，但规则在首个输出前冻结，选点在读取确认轮之前封存；它不是第二轮采集前发生的在线干预。原对应策略在这些新上限下也未超时，因此我们只报告“未观察到后续超限”，不声称该校验已证明降低违约率。有限候选、重复样本和经验余量也不能构成生产硬 SLA 保证。

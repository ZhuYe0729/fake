# Linear 时间占比研究 - 分析报告

## 研究问题

在什么场景下，Transformer 模型中 nn.Linear 层的推理时间占比最高？

## 测试方法

- 模型: Qwen3.5-2B, 4B, 9B (dense BF16)
- GPU: RTX 5090 (5, 6, 7 号卡)
- Batch size: 1, 4, 16
- 输入 token 数: 256, 1024, 4096, 8192
- 输出 token 数: 1 (prefill-only), 32, 128, 256 (prefill-decode)
- 测量方式: CUDA event hook 级别计时 (coarse breakdown)
- 所有 nn.Linear 子模块通过 hook 聚合为 'all_linear'

## 分析与解读

### 峰值与谷值

- **最高 prefill linear 占比**: 62.4% — 模型=9b, batch=16, 输入=256, 输出=1, prefill=497.81248168945314ms
- **最低 prefill linear 占比**: 9.1% — 模型=2b, batch=1, 输入=256, 输出=32, prefill=120.49981689453125ms

### 核心结论 1: Batch Size 是主导因素

对提升 prefill 阶段 linear 占比影响最大的因素是 **batch size**:

| 模型 | bs=1 → bs=16 的 Prefill Linear% 增长 |
|---|---:|
| 2b | 18.0% → 40.3% (+22.3pp) |
| 4b | 23.6% → 44.3% (+20.8pp) |
| 9b | 38.6% → 59.2% (+20.6pp) |

三个模型从 bs=1 到 bs=16 都提升了约 **20pp**，说明增大 batch 是提升 linear 占比最可靠的手段。
这是因为更大的 batch 增加了 GEMM 的 M 维度，使矩阵乘法更加计算密集，从而稀释了 attention 等非 linear 操作的开销。

### 核心结论 2: 模型大小放大效应

大模型始终表现出更高的 linear 占比。例如 batch=16, input=256 时，9B 达到 **62.4%** 而 2B 仅 **36.5%**。
这是因为大模型的 linear 层更宽（GEMM 的 K/N 维度更大），能更好地利用 GPU 计算能力，而 attention 开销增长相对较慢。

### 核心结论 3: Decode 阶段 Linear 占比稳定且偏低

所有模型和配置下，decode 阶段的 linear 占比都稳定在 **21-30%** 的窄幅区间内。
Decode 阶段本质上是 memory-bound（每次只处理 1 个 token，M 维度极小），因此 linear 层的时间占比不高。
Attention 的 KV cache 查找等非 linear 操作占据了约 70% 的时间。

### 核心结论 4: Prefill 与 Decode 的差距随模型增大而扩大

| 模型 | Prefill Lin% | Decode Lin% | 差距 |
|---|---:|---:|---:|
| 2b | 28.5% | 27.4% | +1.1pp |
| 4b | 33.5% | 29.8% | +3.7pp |
| 9b | 48.6% | 30.1% | +18.5pp |

2B 模型的 prefill/decode linear 占比差距几乎可以忽略 (+1.1pp)，但 9B 模型的差距高达 **+18.5pp**。
这意味着对于大模型，prefill 和 decode 的压缩策略应该差异化：prefill 积极压缩 linear，decode 则轻量处理。

### 总结: Linear 占比何时最高？

1. **最大模型 (9B)** + **最大 batch (16)** + **中等输入 (256-1024)** = **~62% linear**
2. 同一模型在 batch=1, input=256 时仅 **~16% linear**，相差近 4 倍
3. 输入长度是次要因素：增加到 ~4096 时 linear 占比上升，之后因 attention 复杂度平方增长而趋于平稳甚至下降
4. Decode 阶段 linear 占比上限约 **30%**，与配置无关

### 对压缩策略的启示

- **Prefill 为主 + 大 batch + 大模型**: Linear 压缩收益最高（可达总时间的 62%）
- **Prefill 为主 + 小 batch**: Linear 压缩收益有限（低至 10-16%），需同时优化 attention
- **Decode 为主**: Linear 压缩上限约 30% — attention 优化是更大的杠杆
- **混合策略**: 大模型应对 prefill 使用激进压缩（如稀疏化），decode 使用快速压缩（如 Marlin）；小模型 (2B) 的 prefill/decode 差异不大，可统一策略

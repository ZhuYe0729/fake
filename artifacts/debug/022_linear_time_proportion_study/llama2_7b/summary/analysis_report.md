## 理论解读

- Prefill 阶段的 linear 是形状近似 `[batch * seq, hidden] x [hidden, out]` 的 GEMM；batch 和输入长度增大后，GEMM 更容易吃满 Tensor Core，因此 linear 占比通常上升。
- 输入过长时，attention core 和 KV/cache/layout 相关开销会随上下文增长，linear 占比可能不再继续上升。
- Decode 阶段每步只处理一个新 token，linear 形状更接近小 M GEMM/GEMV，实际更容易受访存、kernel launch、KV cache 读取和 attention softmax 影响，因此 linear 时间占比通常显著低于 prefill。
- Llama2 是标准 full attention 架构，没有 Qwen3.5 的 hybrid linear attention 层；因此和 Qwen 对照时，应重点区分架构差异、hidden/FFN 宽度、attention backend 和上下文长度。

## 压缩策略启示

- 大 batch prefill 是 linear 压缩最有希望带来端到端收益的区域。
- Decode-heavy 场景不能只看参数量或 FLOPs；如果 measured linear 占比只有 20-30%，Amdahl 上限会很快限制只优化 linear 的收益。

# 162 — Llama8bit基线同输入重放核查

## 来由与范围
- 九小时窗口内优先核查强基线复用的数值一致性。034/035新点复用了017/018同map、同执行代码和输入的完整基线；当前Llama-3.1新点生成Avg仍低于普通INT8，不能预设一定是实现问题或用不同口径降低基线。
- 独立run037只对两模型plain INT8/SQ-INT8/FP8进行原64窗口NLL和各生成任务最前128条的同分组重放。保持原BOS、模板、batch8/4、EOS、256token与完整输入文件SHA。
- 128条从原完整输入的开头连续取，能复现原batch划分；不以随机重分组后的差异断言数值不等价。不改原输入或原基线分数。

## 执行
1. 034/035/036审计完成后启动GPU重放；读取night161保留的精确export缓存，核对method-map、源模型和量化代码，最多6张空闲卡并行。
2. 使用原生成/NLL模块，仅将输出根目录切到037的模型隔离目录；旧source代码、数据、结果不变。记录源码SHA、实际checkpoint、GPU/NUMA、数据SHA、命令和原始输出。
3. 比较64个窗口的NLL均值/最大绝对差；比较每任务128条question_id、reference与逐token输出，报告完全相同条数、首次分歧和对原128子集重算的指标差。
4. 不把重放子集分数同完整benchmark分数作优劣比较。若不一致，先定位输入/权重/运行时差异，再决定必要的完整基线复测；保留旧分数和所有不利结果，不能因为基线更强而替换协议。

## 验收
- 三个原核心run和旧017/018/Qwen主表SHA不变；所有重放样本与原128子集逐项可对应。
- 正式速度无并发干扰；本核查不报告新性能加速或新泛化结果，仅证明或限定基线复用可靠性。
- 发布reviewer2/reviewer5可引用的比较CSV、原始差异及来源，若存在差异如实展示，不强制“通过”。

# 183 — Rebuttal Git 提交与 PRO 6000 大模型交接

## 目标
- 将最近 rebuttal 的代码、配置、结果、日志和文档提交并推送到现有远端，使另一台 PRO 6000 机器 pull 后具备充分上下文。
- 不提交模型权重、编译/下载缓存、临时进程状态等可重建大文件；不删除本地代码、日志、CSV 或文档。
- 保留已有未推送提交与其他工作区改动，不重写历史，不覆盖远端。

## 步骤与验收
1. 盘点 Git、文件大小、忽略规则、依赖子模块和现有 PRO 6000 入口 → 明确可提交文件及外部依赖，防止模型或机器本地设置进入提交。
2. 准备中文交接文档、必要依赖补丁/源码快照、机器路径迁移说明与文件清单 → 新机器能够识别最新结果、重建路径和32B实验缺口。
3. 精确暂存相关源码/结果/文档及合理体积日志；必要时对超大结果采用无损归档并留说明 → 索引无权重、无缓存二进制、单文件符合远端限制；代码和结果保持完整。
4. 检查暂存 diff、文件覆盖与关键文档链接，创建提交并普通 push → 给出 commit、分支、pull 和交接入口；网络或权限障碍如实说明，避免强推或无关修改。

## 边界
- 本轮不在新机器启动GPU实验，不变更实验结论或数值。
- 对本地修改的依赖优先保存可应用补丁及锁定基线，不向第三方 upstream 提交或推送。
- 现有全局 submodule 初始化缺失映射需给出可复现的针对性处理，不假定递归初始化已可用。

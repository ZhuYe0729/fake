# 155 — 将验证保护值纳入DASO提案生成

## 来由与范围
- 用户授权继续优化DASO。029条件增量代理在8个未拟合policy上MAE从旧anchor代理.01497降至.00220，但新128窗口validation将135/126个W4方案的保护值判为约.023–.024，不能通过ε=.01。当前生成提案只优化预测均值，遗漏最终门控的SE和安全余量。
- 029继续原规则完成、保留全部原提案和结果，不修改其模型/选择/确认。030是单独的后续算法实验，设计仅使用029校准与开发validation发现的问题；拟合、残差及协方差全部仅来自029原训练64窗口和8个校准policy holdout，不读取029 confirmation来设计新点。

## 实现与预冻结实验
1. 新增独立可选模块`quality_constraint.py`，不改029冻结核心源码。用同一64窗口上的anchor-relative样本及16组增量样本估计完整协方差；对mask预测mean和σ/√128，保留相关性，预测最终128窗口guard = mean +2SE+.005+残差余量。
2. 残差余量固定为max(0,max八个policy holdout的实测均值−条件加和预测均值)。这只是经验保护/验证统计量预测，不是形式化置信保证。
3. 枚举同65536组mask，在guard目标{.005,.01,.02,.04}下各取LUT最快点。根据只读CPU诊断，预计提案约54/72/90/108个W4模块；实际由冻结公式自动决定，不手选模块。
4. 固定池 = 029条件加和均值提案(0/.005/.01/.04) + 本轮4个guard提案 + BF16/INT8/SQ/full-W4共同anchor，最多10个唯一map。比较mean-only池与cumulative mean+guard池；新方法保留全部旧可行incumbent，不人为削弱对照。
5. 新validation128、confirmation128、16速度输入取unused内部train窗口，排除原128训练、028全部208窗口、029全部272窗口。与030校准数据/其他split不重叠。029均值提案也在新窗口重新测，不能借旧validation质量比较新方法。
6. 同原保护值和预算.01/.04选择；实际calibration E2E为目标，cycle另报。冻结选择后才读030 confirmation；均值与保护值分别报告，不据确认重选。
7. 主版本/mean-only选择及固定anchor统一3轮GPU0测速；新主版本map才补完整三生成，相同map且协议一致的027/028结果可带来源复用。预测质量/可行性、速度、全部分项质量分别报告。

# Qwen3 uniform runtime and speed reanalysis

## 决定与范围
- run014 已证明 eager 发射开销掩盖 W4A16 的 GPU 收益。重新核验速度链路、延迟画像、配置选择和排名；相同量化 map/权重/数值协议的完整质量结果可继承。
- 保留001–014全部数据及现有主表，新增 run015；不因不利结果换协议或删除对照。
- 不将两套权重全部常驻显存当作免费 Graph 修复。优先验证固定地址、按层复用 prefill/decode 存储，保留异步 H2D 和恢复成本。

## 执行与验证
1. 实验局部实现稳定权重地址的阶段复用缓冲区，接入原生 decode CUDA Graph。
   - 对同一 map 比较原 eager、复用缓冲区 eager、复用缓冲区 Graph；核验多次生成/固定 KV 数值、阶段状态、地址稳定性、异步事件顺序和显存。
   - Graph 捕获只在 decode，prefill 保持同协议；不修改共享 CUDA kernel、量化规则或全局时钟。
2. 先统一重测现有固定主表配置。
   - 同一 GPU / NUMA 放置，B8/S2048/O1或64，6GiB BF16 KV，固定输入，独立进程三轮、3 warmup+8 timed、BF16首尾锚点。记录 TTFT、TPOT、E2E、恢复完整周期、初始化/捕获耗时、host/GPU内存和输出变化。
   - 所有候选必须按相同规则运行；捕获失败或显存不可行明确记录，不能混用 Graph 和旧 eager 数字构造排名。
3. 新画像覆盖实际主负载及预定代表负载；重放 DASO DP/精确代理求解及 HAWQ Hessian/ILP。
   - 延迟代价使用匹配新执行方式的完整算子前向，GPU kernel 时间、主机发射和切换成本分开；加和仍为代理，必须用实际 E2E校准/验证。
   - 候选池包括统一/阶段统一强基线；保持质量模型与预算意义，精确求解只指代理目标。选择仅使用 validation/校准，不使用独立 test 挑点。
4. 对新增 map 实测质量；相同 map 继承已验证完整任务。
   - 数值改变或 map 改变才补对应任务；不默认旧配置仍最优，也不默认改运行时后 DASO必胜。
5. 优先更新主表与质量–速度边界，再补代表配置、运行时开销与实测约束分析。
   - 保留新旧版本及逐项来源，说明初始化/Graph捕获成本、显存变化及计时范围；无盲目全量重跑。

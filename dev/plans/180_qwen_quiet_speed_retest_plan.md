# 180 — Qwen空闲GPU3/4正式速度复测

## 范围与假设
- 用户授权在目前空闲的GPU3/4开始剩余速度测试。启动检查两卡显存各约2MiB，利用率0/1%；不占用其他卡，不结束他人的进程。
- 仍测四组核心负载：B8/S2048/O64、B4/S2048/O64、B8/S4096/O64、B8/S2048/O128，对应三种独立Prefill-only与四种P+D。BF16参考、HAWQ/DASO各均衡及速度点不变；PP共同端点只测一次。
- 精度沿用050完整原协议任务与049逐B/S/O NLL，不重跑、不按新速度选点。旧速度及暂估表保留。本轮不修改数值内核、精度配置或模型权重。
- 主结果固定GPU3；GPU4为预先确定的独立硬件复核。两卡各自完整三轮、各自BF16首尾归一化，分别展示，不混合绝对耗时或选择更有利的卡。正式工作串行，避免本任务在另一张卡上的加载/编译/恢复造成干扰。

## 执行与验收
1. 建立独立runs/051，复制049数值/计时实现并仅增加设备身份与记录信息；硬链接复用050八个checkpoint，复制并核对旧测速输入、引擎、策略、数值源码与精度来源SHA → 不重新导出权重，旧数据不变。
2. GPU3先完整跑三轮，GPU4再独立完整跑三轮；每轮BF16首尾，轮换策略及负载顺序；每case 5次预热＋10次正式测量，与049同一Graph/4232上下文/32768 token预算/KV6GiB → 共54正式进程、234个case轮次、2340次正式计时，预热另存。
3. 在空闲卡加锁启动，核对Torch CUDA与NVML UUID、绑定每卡CPU组/NUMA；记录卡上进程、时钟/温度/功耗及其他卡利用率。外部占用时等待同一卡恢复；明确资源失败保留后原参数重试，任何计时数值不作为重跑/删轮依据 → 全部日志、失败尝试、逐次计时和代码快照保留。
4. 分卡统计TTFT、TPOT、请求E2E和包含恢复的cycle；各轮BF16首尾均值归一化，再报告三轮速度比中位数和范围。保留5%波动门槛及与HAWQ速度点的逐轮配对次数 → 显示不确定和不利结果，不将Max-speed名称解释为每负载全局最快。
5. 自动按进度生成新正式速度与050实测Avg/049 NLL合表，主卡结果和复核卡结果分开；逐样本重算速度、验证源SHA和表格 → 完成后更新清晰入口并追加impl180。若仍有波动，按预定门槛标记，不隐藏或替换。

# Qwen3 W4A16 decode / TPOT diagnosis

## 范围与假设
- 排查 run013 中 W4A16 Linear 微基准较快、完整 TPOT 较慢的差异；不预设量化必胜或已有主表一定错误。
- 新建 run014，原001–013、主表及失败记录保留。先做最小诊断，确认因果后才扩大重测。
- 使用空闲 GPU0、NUMA0 CPU0–7，沿用 B8/S2048/O64、6GiB BF16 KV、固定输入；不修改全局时钟或其他任务。

## 步骤与成功条件
1. 保存相关代码、配置、输入和运行环境；复现 BF16 / NVFP4 W4A16 / INT4 Marlin 的 TPOT。
   - 验证：相同输入、输出 token 数、KV 起始长度、CPU 放置；记录绝对耗时与运行设置。
2. 分解小矩阵 kernel、Python/CPU dispatch、完整模型和阶段管理开销；对相同形状与 KV 长度作受控对比。
   - 验证：CPU/CUDA trace 与无 profiler 计时分开，保留原始 trace、同步/分配记录；不把算子时间之和当作完整 TPOT。
3. 针对已证实原因做最小实验局部修复或控制，并以交错重复确认收益及数值一致性。
   - 验证：干预前后只有目标变量改变，固定输入和权重，检查输出误差/生成；未定位原因时明确剩余假设。
4. 记录结果和对 rebuttal 主表的影响。必要时统一重测受影响方法，不直接用有利的单次诊断替换主表。

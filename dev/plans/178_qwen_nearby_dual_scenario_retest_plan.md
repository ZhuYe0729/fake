# 178 — Qwen邻近负载双场景强基线复测

## 目标与选择依据
- 用户要求围绕已有Qwen主场景，选择合理且时间可控的多种配置，同时覆盖Prefill-only和P+D，只比较DASO与HAWQ-V3，先测真实NLL、后续再决定下游任务。
- 第一批固定四种B/S/O：8/2048/64（原场景）、4/2048/64（批量减半）、8/4096/64（输入加倍）、8/2048/128（输出加倍）。三种独立B/S对应Prefill-only，四种对应P+D，共七个场景。
- 第二批候选16/2048/64、8/1024/64先于GPU输出固定；用户随后选择约1–2小时优先核心配置，因此本轮不启动第二批。全部计划配置及已测结果保留，不按结果删除不利项。
- 固定迁移主表DASO/HAWQ的均衡、速度优先两个点，速度优先不是逐负载最大值。Prefill两个速度端点为同map，共用测量。BF16只作为NLL/速度参照，不扩展其余baseline或做逐负载参数搜索。

## 实施与验收
1. 冻结runs/049：独立代码、输入/质量窗口、配置签名、顺序、指标与计时协议 → 所有新数字可追溯，旧040/048不变；中心输入与048逐token相同。
2. 先在空闲GPU统一测中心与邻近配置；统一引擎容量、Graph捕获尺寸、CPU/NUMA绑定，预热与重复次数固定，政策/负载顺序轮换，BF16首尾锚定 → 保存每次绝对耗时、真实输出token数、硬件遥测与权重一致性；全轮次纳入，中心不稳定时增加预定诊断而不筛轮次。
3. 实测NLL：Prefill用完整prompt logprobs（每窗S−1 tokens）；P+D用真实KV逐token teacher forcing（每窗O tokens），每负载64个公开WikiText窗口，按目标batch运行 → 与同负载BF16配对均值/SE和窗口计数核验，不充当下游任务Avg或新的盲测声明。
4. 首批按七场景发布DASO/HAWQ各两个点，Prefill TTFT与P+D TTFT/TPOT/E2E/cycle分列，NLL同表，并展示全部重复范围 → 对速度或质量尚不稳定的点明确标记；后续下游任务未执行。
